# 우리 산 수익 계산기

임업통계 마이크로데이터로 **임가별** 수익률을 예측하고, 무엇을 바꾸면 나아지는지까지 답하는 시스템

**2026년 임업통계 활용 경진대회 · 데이터 분석 부문 · 팀 임과 함께**

- 웹 서비스 <https://forestry-roi-predictor.onrender.com> — 무료 호스팅이라 첫 접속에 1분쯤 걸릴 수 있습니다
- 분석 보고서 [`data_analysis_report.md`](data_analysis_report.md)
- 제출 서류 안내 [`docs/제출_안내.md`](docs/제출_안내.md)

## 무엇이 문제였나

산림청은 임가경제조사·임산물생산비조사 등 국가승인통계를 매년 내고 마이크로데이터까지
공개합니다. 그런데 임가에게 돌아오는 형태는 대부분 **집단 평균**입니다.

문제는 임업 수익의 흩어짐이 지나치게 크다는 데 있습니다. 임가경제조사 4,438개 표본의
ROI는 **평균 155.5%, 표준편차 216.7%p** — 표준편차가 평균보다 큽니다. 이런 분포에서
평균은 대표값 구실을 하지 못합니다.

실제로 지역별×업종별 평균을 그대로 예측값으로 쓰면 **Test R²는 0.0428**에 그칩니다.
현장에서 널리 쓰이는 "같은 지역, 같은 품목 평균을 참고하라"는 방식이 개별 임가의
수익 변동을 4%밖에 설명하지 못한다는 뜻입니다.

## 결과

동일 분할·동일 지표로 잰 값입니다.

| 모델 | Test R² | RMSE (%p) | 베이스라인 대비 |
|---|---:|---:|---:|
| 산림청 방식 (지역×업종 평균) | 0.0428 | 192.03 | — |
| 선형회귀 | 0.1295 | 183.13 | 3.02배 |
| **Model A** — 임가경제조사, Optuna XGBoost | **0.1736** | 178.44 | **4.05배** |
| **Model B** — 임산물생산비조사 | **0.6243** | 101.33 | **5.95배** |
| **패널 구조 활용** — 직전 연도 실적 결합 | **0.2798** | 167.20 | **10.2배** |

예측구간(P10~P90) 실측 포함률 — Model A **78.2%**, Model B **76.5%** (명목 80%)

> Model A의 0.1736은 절대 수치로 높지 않습니다. 이는 모델의 한계가 아니라
> **임가경제조사 총괄표가 담을 수 있는 정보의 한계**입니다. 산의 수령·수종·경사·판로 같은
> 결정적 변수가 총괄표에 없습니다. 이런 변수를 담은 임산물생산비조사(Model B)에서는
> R²가 0.62까지 올라갑니다. **두 모델의 격차 자체가 "어떤 자료를 더 모아야 하는가"에
> 대한 답입니다.**

## 이 분석에서 지킨 것

**성능보다 정직을 택했습니다.** Model B는 1차 학습에서 R² 0.9102가 나왔습니다.
임업 수익 예측에서 비현실적이라 판단해 피처–타깃 상관을 전수 감사했더니
`건표고_소계수량`과 ROI의 상관이 0.885였습니다. 총생산액·부가가치·등급별 수량이
차단 규칙을 통과하고 있었습니다. 규칙을 넓혀 재학습하니 최고 상관이 **0.885 → 0.344**로
내려가고 R²는 **0.9102 → 0.6243**이 되었습니다. **그 0.62가 실제로 쓸 수 있는 숫자입니다.**
→ [`src/preprocess_cost.py`](src/preprocess_cost.py)의 `LEAKY_PATTERNS`

**분할도 의심했습니다.** 임가경제조사는 패널이라 행 단위로 무작위 분할하면 같은 임가가
학습과 시험 양쪽에 들어갑니다. 실제로 시험셋의 **66.9%**가 학습셋과 임가를 공유하고
있었습니다. 임가 단위로 다시 나눠 재보니 R² 0.1755 → 0.1574로 fold 간 표준편차(0.0321)
안이었습니다. 영향이 제한적임을 확인했고 보고한 수치는 그대로 유효합니다.
→ [`src/audit_split.py`](src/audit_split.py)

**한계를 감추지 않았습니다.** 기상 결합이 예측력을 거의 못 올린 것, Model A의 낮은
설명력, 표고류 표본이 적어 품목별 R²가 음수(−0.052)인 것도 모두 보고서와 화면에
그대로 적었습니다.

**쓸 수 없는 조언은 하지 않았습니다.** 반사실 처방에서 임지 규모를 제외했습니다.
"산을 1ha 미만으로 줄이면 수익률이 오른다"는 결과는 통계적으로 참일 수 있으나
땅을 팔라는 말이라 조언이 될 수 없습니다.

## 예상 밖의 발견

작목 조합의 위험 분산을 계산하다 나온 것입니다.

ROI가 흩어지는 원인은 **연도 효과**(그해 시세·작황)와 **임가 효과**(같은 해 같은 작목
안에서도 임가마다 다름) 둘입니다. 작목을 섞어 줄일 수 있는 것은 앞의 것뿐입니다.
뒤의 것은 그 임가의 특성이라 어느 작목을 하든 따라옵니다.

최적 조합의 연도 변동은 ±8.6%p인데 **임가 격차는 ±134.0%p로 15.6배**입니다.
실제로 밤 기준 선도임가(206곳)의 ROI 중앙값은 207.7%, 그 외(944곳)는 29.7%입니다.

**무엇을 심을지 고르는 것보다 어떻게 하느냐가 수익을 훨씬 크게 가릅니다.**
이 프로젝트의 출발점 — "집단 평균이 아니라 임가별로 계산해야 한다" — 를
데이터가 스스로 증명한 셈입니다.

## 기능

| 단계 | 하는 일 | 기법 |
|---|---|---|
| 예측 | 얼마나 남을지 **구간과 함께** 제시 | XGBoost + 분위수 회귀 |
| 설명 | 왜 그 숫자가 나왔는지 분해 | TreeSHAP |
| 처방 | 무엇을 바꾸면 되는지 탐색 | 반사실 격자 탐색 |
| 비교 | 비슷한 임가는 어떤지 | 최근접 이웃 (로그 척도) |
| 전략 | 언제 팔지 · 무엇을 섞을지 | KAMIS 시세 · 평균–분산 최적화 |

그 밖에 등급 전환 시뮬레이션, 수령별 수익성, 지역 특화도(LQ), 가공 손익분기,
보조사업 지렛대 분석.

화면은 임업 종사자가 쓸 수 있는 말로 썼습니다. "ROI 예측"이 아니라 "얼마나 남을까",
"포트폴리오 최적화"가 아니라 "한 작목에 몰아도 될까"입니다.

## 실행

```bash
pip install -r requirements.txt

# ① 전처리
python src/preprocess.py          # 임가경제조사
python src/preprocess_cost.py     # 임산물생산비조사 (누수 차단)

# ② 학습 — NVIDIA GPU 사용 (tree_method=hist, device=cuda)
python src/train_optuna.py        # Model A + 3종 벤치마크
python src/train_cost.py          # Model B + 품목별 성능
python src/train_quantile.py      # 예측구간 P10/P50/P90
python src/train_panel.py         # 패널 구조 활용
python src/tune_panel.py          # 패널 모델 전용 탐색

# ③ 검증
python src/audit_split.py         # 분할이 성능을 부풀렸는가

# ④ 분석 계층
python src/insights.py            # 등급·수령·선도임가
python src/production.py          # 지역 단가·특화도·가공
python src/management.py          # 출하시기·판로
python src/subsidy.py             # 보조사업 실효 ROI
python src/region_map.py          # 시군구 단가 지도
python src/portfolio.py           # 작목 조합 위험 분산

# ⑤ 산출물
python src/make_figures.py        # 도표
python src/make_report.py         # 분석 보고서
python src/make_docx.py           # 제출본 (붙임3)

# ⑥ 서비스
cd web && npm install && npm run build && cd ..
uvicorn api.main:app --host 0.0.0.0 --port 8000
```

탐색 규모는 환경변수로 조절합니다.

```bash
N_TRIALS=300 N_GPU=2 python src/train_optuna.py
```

## 배포 메모

무료 등급(512MB · 0.1 CPU)에 맞추느라 손본 것들입니다. 같은 제약에서 서빙하실 분께
도움이 될 만한 것만 적습니다.

- **부스터 지연 적재** — 다섯 개를 미리 다 올리면 166MB입니다. xgboost가 8MB짜리
  모델을 메모리에 30MB 넘게 펼치기 때문입니다. 실제로 쓸 때 올리되, 첫 화면이 반드시
  쓰는 둘만 기동 직후 예열합니다. 첫 예측이 10초에서 0.83초가 됐습니다.
  → [`api/services.py`](api/services.py)
- **스레드 고정** — xgboost가 호스트가 보고하는 코어 수만큼 스레드를 띄우는데
  실제 지분은 0.1개라 서로 나눠 갖느라 오히려 느려집니다. `nthread=1`로 묶으니
  처방 응답이 67초 → 8초가 됐습니다.
- **판본 고정** — 학습 환경과 어긋나면 배포가 성공해도 예측값이 달라집니다.
  실제로 xgboost를 2.1.3으로 두었을 때 같은 입력에 111.0 대신 −44.2가 나왔습니다.
  화면은 멀쩡해서 겉으로 드러나지 않습니다. 값을 직접 맞춰 봐야 압니다.
